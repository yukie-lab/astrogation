# PHASE 1 — 航路カタログ

> 前提: Phase 0 ゲート承認済み。CLAUDE.md §5 は L7 準拠の追記版
> (三層区間: [R]床 c(x) / [N]実効 g̲(x) / [R]天井)であること。
> 使用してよい部品は Phase 0 の認証済みライブラリのみ。
> 新しい式を論文から追加転記する場合は、式台帳(L2)に追記し
> 認証テストを先に書く(Phase 0 と同じ規律)。

## 目的

Le の許容性拘束をすべて課した恒星間機動の全域カタログを計算する。
出力の二本柱は **表A(ラピディティ階段)** と **表B(ミッション表)**、
新規性の核は **フロンティア騎乗の時間最適プロファイル群**。
全行に G3(二経路照合)を自動適用し、全数値に権威ラベルを付す。

## 物理設計の要点(実装前に理解せよ)

- 燃料 m_f/m₀ = e^(−3Δη) は**距離非依存** [R]。ゆえに表Aは行き先を持たない
- 機動型は排気の向き履歴ごと定義する: **flyby**(加速のみ、Δη)/
  **到着**(加速+反転減速、2Δη)/**往復**(4Δη)。減速バーンでは
  排気ローブ(後方極)が**進行方向=目的地側**を向く。この向き履歴は
  Phase 2 の観測署名の主入力なので、必ず保存する
- 時間最適でのみフロンティアが効く。x(u) は放射で単調減少し、
  天井 ½(1−x(u)) は**バーン中に広がる**(動く壁)。[N]実効層では
  g̲(x) の定義域 x∈[0.1,0.7] を出た瞬間に例外(外挿禁止は実装済み)

## タスク

### 1-1. 拘束モジュールの三層化
`frontier.py` を拡張し、`tier="floor" | "effective" | "ceiling"` で
c(x) [R] / g̲(x) [N] / min(½(1−x), 厚壁窓) [R] を返す統一 API。
c(x) は v3 (48) 一式(Phase 0 補助認証済みの 5 点で回帰テスト)。

### 1-2. 表A — ラピディティ階段(行き先非依存・全行 [R])
η ∈ {0.1, 0.24, 0.5, 1, 2, 3, 5, 8, 12} について:
到達速度 β、γ、残存質量率 e^(−3η)、放射質量率、
**Füzfa 比較列**: 理想光子ロケット e^(−η) との比 e^(2η)
(=「乗客の座席の値段」。差分声明 L5 の定量版)。
η=0.24 行は App K 実働バーンと一致すること(C4 の再確認を兼ねる)。

### 1-3. 表B — ミッション表
行き先(距離は conventions.md に典拠つきで固定):
プロキシマ・ケンタウリ 4.25 ly / TRAPPIST-1 40.5 ly /
いて座A* 2.6万 ly / アンドロメダ銀河 254万 ly。
機動型: flyby / 到着 / 往復 × 巡航ラピディティ数点。
各セル: 燃料、**地球座標時間**、**船内固有時間**(加速区間は双曲運動、
巡航区間は γ で縮む標準運動学)、拘束充足の判定。
「固有時間 50 年以内」の等高線が引ける密度でサンプルすること
(アンドロメダ行きの寿命内条件 η≈11.5、質量比 ~10⁻¹⁵ が読めること)。

### 1-4. フロンティア騎乗プロファイル(新規性の核)
時間最適問題: 与えられた Δη を最短(地球時間/固有時間の両方)で
達成する λ(u) ≤ tier(x(u))、x(u) は飽和制御則で進化。
- 三層それぞれで解き、**括弧つき区間**として提示:
  [R]床(証明済み安全・極めて遅い)≤ 真の最適 ≤ [N]実効 ≤ [R]天井由来の下限時間
- 拘束アークの切替構造(内点弧 vs 拘束弧)を記録。動く壁に沿う
  「フロンティア騎乗」区間の存在と長さがこのフェーズの主結果
- [N]層で x が [0.1,0.7] を出るプロファイルは、その時点で層を
  [R]天井にフォールバックし、フォールバック点を記録(黙って続行するな)

### 1-5. SI 正直レイヤー
無次元カタログに R = 100 m / 1 km / 10 km の換算列を付す:
殻質量 m = xR/2 → kg・地球質量・太陽質量、ピーク光度 L = −ṁ → W・L☉。
「惑星〜恒星質量の物体が超新星級の光度で燃えながら進む」桁が
表から直接読めること。units.py(C7 認証済み)以外での換算を禁ず。

### 1-6. 全行 G3 自動化
カタログ生成パイプラインに二経路照合を組み込む:
閉形式(Tsiolkovsky・arccosh 距離)vs ODE 積分。相対 1e-8 超の行は
**カタログに載せない**(欠番として理由を記録)。不一致が 1 行でも
出たら STOP(CLAUDE.md §8-2)。

### 1-7. Phase 2 への出力規約
各プロファイルを構造化ファイル(形式は裁量)で保存:
u 格子、a(u)、m(u)、v(u)、x(u)、**排気軸の向き履歴**、L(u) = −ṁ(u)、
権威ラベル、G3 照合結果、生成コミットハッシュ。
Phase 2 はこのファイル**のみ**を入力とする(再計算させない)。

## このフェーズ特有の STOP

- G3 不一致行の発生
- 時間最適ソルバーが収束しない(→ 定式化を報告。数値の力押し禁止)
- 三層の順序逆転(床 > 実効 など)を検出 — これは転記か実装の誤りであり、
  修正前に必ず報告(論文側の問題の可能性も含む)

## 禁止(このフェーズ固有)

- スペクトル・観測装置性能への言及(Phase 2 の領域)
- Λ > 0 の Zermelo ドリフト(将来課題として ASSUMPTIONS に記録済み扱い。
  実装しない)
- [R]床層の遅さを「物理的不可能」と表現すること(それは証明の保守性であり
  自然の限界ではない。権威ラベルの言葉で書く)
- 多段ドッグレッグ機動(余裕があれば一例のみ、DoD 外)
